## 一、常用命令

在项目根目录（`blog/`）下执行：

```bash
npm install      # 首次或换电脑后：安装依赖
npm run dev      # 本地预览，默认 http://localhost:4321/blog/
npm run build    # 构建静态站点到 dist/
npm run preview  # 本地预览构建结果
```

发布（推送后 GitHub 会自动构建部署，约 1 分钟）：

```bash
git add -A
git commit -m "更新内容"
git push
```

> 部署完成后若浏览器还是旧内容，用 `Ctrl + F5` 强制刷新。

## 三、写一篇新文章

在 `src/content/blog/` 目录新建一个 `.md` 文件，例如 `unity-tips.md`：

```markdown
---
title: '文章标题'
description: '一句话摘要，会显示在卡片和列表里。'
pubDate: '2026-04-01'
category: 'Unity DOTS'
tags: ['Unity', '性能优化']
---

正文用 Markdown 编写。

## 二级标题

- 列表
- **加粗**、`行内代码`

```csharp
// 代码块
Debug.Log("Hello");
```
```

- `title` / `description` / `pubDate` / **`category`** 是必填；`tags` 可选。
  **少写一个必填项，构建会直接失败**（这是故意的，宁可报错也不要静默出错）。
- **文件名（去掉 `.md`）就是网址**。注意本站网址有**两层 `blog`**：
  `unity-tips.md` → `.../blog/blog/unity-tips/`（第一层 `blog` 是站点路径，第二层是文章列表目录）。
- 文件名里的空格和大写会被自动规范掉：`unity dots job.md` → `unity-dots-job`。
  英文文件名更稳妥（中文文件名会让网址变成编码后的形式）。
- **改文件名 = 换网址**，老的链接会 404（本站没有做重定向）。

## 五、给文章分类

每篇文章的 frontmatter 里有一个 **`category`**（必填）。写什么字符串，就归到哪个分类——
**不需要在任何地方注册分类**，也不用新建页面。

```markdown
---
title: '文章标题'
description: '一句话摘要'
pubDate: '2026-04-01'
category: '性能优化'      # ← 同一个字符串 = 同一个分类
---
```

**文章页（顶部导航「文章」）会按分类分段显示**：先出现分类名和篇数，下面就是该分类的文章卡片。
分类多的排在前面，每组内部按发布日期从新到旧。就这么简单，没有独立的分类页面。

| 你会看到 | 说明 |
| --- | --- |
| 文章页顶部「共 N 个分类 · M 篇」 | 概览 |
| 文章页里每个分类一段 | 分类名 + 篇数 + 该分类的卡片 |
| 文章卡片右上角 | 分类徽章（在首页「最新文章」里也能看到归属） |
| 文章页标题下 | 分类徽章（只作展示，不可点） |

要改的话：

- **改分类名**：直接改 frontmatter 里的字符串。大小写和空格差异不影响归类
  （`Unity DOTS` 和 `unity  dots` 会算同一个分类），但**显示的是你写的那份原文**，
  所以同一分类最好写法统一。
- **加新分类**：给某些文章写一个新的 `category` 值就行，文章页会自动多出一段。
- **调整顺序**：分组按「文章多的在前」排列；某组内部按 `pubDate` 从新到旧。
  想换位置最直接的办法是调整各分类的文章数量，或改 `src/utils/categories.ts` 里
  `groupPostsByCategory()` 末尾的排序。
- **拆细分类**：现在 5 篇文章都是 `Unity DOTS` 一个分类，所以文章页只有一段。
  想让分段更丰富，把各篇的 `category` 改成不同的值即可（例如「性能优化」「渲染」）。
- **分类的锚点**：每段有 `id`（由分类名转成，`Unity DOTS` → `#unity-dots`），
  所以可以直接用 `…/blog/blog/#unity-dots` 跳到某一段。

## 六、换背景风格

站点右下角有个**背景切换器**（图层图标），点开后可以在 5 套风格里选，**选择会记在这台浏览器里**
（`localStorage`），刷新和翻页都保持。访客各自选各自的，互不影响。

| 预设 | 效果 |
| --- | --- |
| 星野 `starfield` | 漂浮的粒子星野（默认），鼠标移动有视差 |
| 网格 `grid` | 赛博风格的网格地平线，向远处滚动 |
| 波浪 `waves` | 起伏的粒子波场，颜色随高度变化 |
| 经典 `classic` | 最初的效果：方形粒子 + 两个线框圆环 |
| 极简 `minimal` | 关掉 3D，只留纯色渐变（最省电，**不加载 three**） |

想改的话：

- **改默认风格**（访客没选过时用哪套）：`src/scripts/background/catalog.ts` 的 `DEFAULT_PRESET`。
- **改名字 / 说明文字 / 增删预设**：同一个文件的 `PRESETS`。
- **改某套风格的样子**：改 `src/scripts/background/impl/` 下对应那个文件（`starfield.ts` / `grid.ts` / …）。
- **加一套全新的风格**：照着 `impl/grid.ts` 新建一个文件，导出 `create(...)`，然后在 `catalog.ts`
  的 `PRESETS` 与 `src/scripts/background/index.ts` 的 `MODULE_LOADERS` 各加一行。
- **不想要这个切换器**：把 `src/components/ThreeBackground.astro` 里的 `.bg-switcher` 那段删掉即可
  （背景本身照常工作，只是访客没法自己换）。

> 系统里开了「减弱动态效果」的用户，第一次访问会默认落到「极简」；他们手动选过之后就听他们的。

## 七、部署说明（已配好，一般不用动）

- 仓库里已有 `.github/workflows/deploy.yml`，推送 `main` 分支即自动构建并发布到 GitHub Pages。
- 站点配置在 `astro.config.mjs`：`site` 与 `base`（当前 `base: '/blog'` 对应 `https://<用户名>.github.io/blog/`）。

如果以后想让网址变成根路径（`https://<用户名>.github.io/` 而不是 `/blog/`），需要把仓库改名为 `<用户名>.github.io`，并把 `astro.config.mjs` 的 `base` 去掉。
